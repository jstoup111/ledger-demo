# Track: seed-recorded-times

Track: product

The change alters what an audience sees. The transaction table's **Recorded** column is one of three
columns on the only page this project has, and today it repeats a single value down every seeded row.
Fixing that is a change to displayed content, judged by whether the column reads as real history from
across a room — a product requirement, not an internal refactor. It also changes what the seeded
dataset demonstrates on stage (the equal-timestamp tiebreak becomes a visible, deliberate pair rather
than an accident of every row sharing one instant), which is likewise audience-facing.

`/prd` therefore runs, and the FRs are stated as observable properties of the displayed data.
